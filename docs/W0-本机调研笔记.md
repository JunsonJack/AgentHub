## 二、产品前提得到本机数据印证

**Skill 重复是普遍现象**（这正是"中央库 + 收编"要解决的）：

| 目录对 | 重名 skill 数 |
|---|---|
| `.claude/skills` ↔ `.zcode/skills` | 7 |
| `.claude/skills` ↔ `.agents/skills` | 7 |
| `.zcode/skills` ↔ `.agents/skills` | 5 |

重名示例：`agent-browser`、`git-commit`、`evolver`、`codexhost-delegation`、`computer-use`、`baoyu-comic`、`pptx`、`find-skills` 等在 2~3 个目录各存一份。收编（adopt）+ dry-run 差异对比（同名目录内容是否一致）应作为 MVP 的高优先能力。

## 三、对规划的直接修订建议

1. **首批 Agent 表更新**：Codex skill 目录从"待调研"改为 `~/.codex/skills`（存在）；ZCode MCP 路径精确为 `~/.zcode/cli/config.json`（`mcp.servers`）；Cursor 增补 `~/.cursor/skills` 与 `hooks.json`。
2. **作用域模型**：Claude Code 的项目级 MCP 与全局共存于 `~/.claude.json`（`projects.<path>.mcpServers`）；Codex 有 `[projects.'…']` 节。数据模型 `Assignment` 需带 scope 字段（global / project:<path>），不能只按 Agent 粒度。
3. **敏感文件清单**（Connector 永不写入、只做展示脱敏）：`~/.zcode/v2/credentials.json`、`~/.zcode/v2/provider_config.json`、`~/.codex/auth.json`、各配置里的 `env` 值。
4. **插件包（P2）提前有据**：Codex `[plugins."name@marketplace"]` 节 + `~/.zcode/cli/plugins/installed_plugins.json`，P2 做 bundle 管理时可直接复用这两个探测点。
